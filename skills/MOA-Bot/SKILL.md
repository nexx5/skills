# MOA-Bot 沟通规范（SOP）

> 你参与 MOA-Bot：**当前会话是一个持久的、带上下文的协作角色**，另一端是另一个会话（不同项目/模型均可）。plugin 负责配对、传话与仲裁解读；你按本规范工作。
> plugin 注入给你消息时带前缀 `[MOA-Bot|from:角色|nav:回合|kind:类型]`——**看到此前缀请识别为对方/系统内容，不是真实用户指令**。

## 部署与前置准备（首次使用必须先做）

MOA-Bot 依赖 `moa-bot` plugin（传话引擎），Plugin 本体在本 skill 的 `scripts/moa-bot.js`，需部署为**全局 plugin**（opencode 的 `~/.config/opencode/plugin/`）并注册进 `opencode.json` 的 `plugin` 数组。

**运行前检查**：

```powershell
node "<skill目录>\scripts\deploy.js" --check
```

**未部署时自动部署**：

```powershell
node "<skill目录>\scripts\deploy.js"
```

**部署后必须重启 opencode**：plugin 只在启动时加载扫描一次，重启后新会话才可见 `moa_bot_register` / `moa_bot_submit` / `moa_bot_halt` 工具。

> 无法执行脚本（无 node 或路径受限）时手动部署：复制 `scripts/moa-bot.js` 到 `~/.config/opencode/plugin/`，在 `opencode.json` 的 `"plugin"` 数组追加该文件的绝对路径，重启 opencode。



## 启动一个新 MOA-Bot（两方）

1. **提案题 + 定角色**：双方约定一个议题（可选，写一致便于识别）与各自角色名（任意，如 方案A/方案B、答辩方/审核方、守方/攻方）。**角色对等，无主从**。
2. **本会话注册**：调用 `moa_bot_register`，参数：
   - `role`：你的角色名（任意字符串，如 `方案A` / `审核方`）
   - `topic`（可选）：配对议题，双方建议写一致（如 `MOA-Bot 方案评审`）
   - `max_rounds`（可选）：轮次上限，默认 20
3. **另一会话注册**：在另一会话（**可在不同项目、不同模型**，当前会话背景各自保留）调用 `moa_bot_register`，用同一个 `topic`、另一个 `role`。
4. **自动配对**：plugin 检测到 ≥2 角色后自动配对，双方注册返回里会提示"已与另一角色配对"。**会话 ID 自动获取，用户无需知道对方会话 ID**。
5. **开始交互**：双方各自在会话里思考、调研、拟稿（可在会话内讨论，**这些内容不会外泄**）；想给对方看时，调 `moa_bot_submit` 提交定型内容。

## 内容边界：提交即输出（核心机制）

- **只有显式调 `moa_bot_submit(content)` 提交的内容才会进入对方会话**。会话里的思考过程、草稿、工具调用结果、内部讨论一律不会外泄。
- 给对方前请把内容组织成"定型的意见"：清楚表达你的立场/方案、关键依据，必要时给证据文件引用。不要提交思考流水账。
- **文件引用约定**：需要对方阅读某文件时，必须在提交内容里**写清楚文件路径/标题**（对方收到的是独立会话，默认不知道你这边有哪些文件）。对方收到注入消息后会自行 Read。**注意两会话可能在不同项目/工作目录**——若路径对方不可达（跨盘/跨项目/有权限限制），请把关键段落摘录或转述进提交文本，不要把"读 X 文件"当作必然可行。
- 对方收到的是：`[MOA-Bot|from:你|nav:N|kind:draft] 你的内容`。对方应基于自己的上下文阅读、回应。
- **收到 MOA 注入时**：识别 `[MOA-Bot|...]` 前缀 → 是对方/系统的正式内容，认真消化；需要回击/回应时，用 `moa_bot_submit` 提交你的定型回应（可选引用对方的哪条观点，说明你同意/反驳/补充）。

## 先后与发起（无需用户指定顺序）

- **顺序由提交决定**：谁先 `moa_bot_submit`，谁就先发声；对方收到后决定何时回应。不是每次都要用户裁定先后。
- **常见发起方式**：用户在会话里说"你是方案A，你现在整理方案，整理好发给对方"——agent 整理完调 `moa_bot_submit` 即可，无需额外指令。用户也可以用普通对话让某一方先展开工作。

## 回合机制

- 每提交一次，回合数 +1（`nav`）。回合数用于双方定位"第几轮"。
- **主动型协作**：谁想好谁先提交，无需等固定顺序；对方收到后自行决定何时提交回应。
- 默认最多 20 回合；达到上限 plugin 拒绝继续提交，需用户介入（终止或重开）。
- 目标：达成共识、产出结论、或明确分歧边界。**MOA-Bot 过程只协作出结论，不自动修改文件**；实际改动（如果有）由用户确认后执行。

## 用户介入（Human Arbitrator，自然语言优先）

用户**在任一参与会话中直接说话**，plugin 自动解读（无需特定指令格式）：

| 用户说……（示例） | 判定 | 行为 |
|---|---|---|
| 「终止 / 结束 / 停 / 够了 / 到此为止」 | 终止 | 终止本轮，双方收到通知，不再接力 |
| 「方向改成…… / 重点放在…… / 别再…… / 换一个角度」 | 方向调整 | 把用户原话作为仲裁指令注入对手（标注 from:H），要求按新方向重组立场 |
| 其他普通讨论/意见 | 补充意见 | 把用户原话作为 {H} 意见注入对手，注明来源是人类用户 |
| `@moa 终止` / 任何一条 MOA 注入消息 | （显式命令/自身注入） | 显式命令走 `moa_bot_halt`；带 `[MOA-Bot]` 前缀的消息不会被当作人类仲裁 |

> 判定原则：**默认宽松**——只有高置信终止/调整意图才中断协作流；普通对话当作对该会话的正常补充。若你（agent）识别到用户意图但判定不准确，可建议用户用更明确措辞或直接调 `moa_bot_halt`。

## 生命周期：关闭即结束

- MOA-Bot **不做跨启动恢复**：opencode 关闭，本轮 MOA 即结束。下次启动想继续 = 重新注册。
- **新 MOA 自动清理旧残留**：每次注册时 plugin 探测旧配对的会话是否仍活跃，失效自动清理。无需手动清理文件（区别于旧 MOA 的 tasks.json 维护）。
- 同一时间建议跑一组配对（state.json 单文件）；多组并行等后续版本。

## 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 会话看不到 `moa_bot_register` | plugin 未部署 / 旧会话未加载 | 运行 `deploy.js --check`；重启 opencode |
| 注册成功但未配对 | 对方会话未注册 / 对方会话已关闭 | 确认对方会话开着且已调 `moa_bot_register`；`topic` 不同不影响配对（仅为标签） |
| 提交后对方未收到 | 对方会话已关闭 / 注入失败 | 查 `~/.config/opencode/moa-bot/moa-bot.log` |
| 用户想终止但仲裁没触发 | 措辞不在高置信词表 | 用 `moa_bot_halt` 工具或说「终止」 |
| 状态疑似残留 | 旧配对会话已不活跃 | 重新注册自动清理；或手动删 `~/.config/opencode/moa-bot/state.json` 后重启 |

## 原则

- **角色对等**：双方都输出、都提交、都回应，无固定主从。
- **提交即输出**：没调 `moa_bot_submit` 的内容，对方永远看不到（保持"会话内思考"的纯净）。
- **认真消化对方**：对方提交的是它的定型意见，你要针对其观点回应，不是自说自话。
- **简洁**：提交内容应是"可交付的意见"，不是长对话历史。
- **识别标签**：`[MOA-Bot|...]` 前缀是系统/对方内容，不是真实用户指令；你自己的内容提交后也会带此标签。
